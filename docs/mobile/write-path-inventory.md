# Write-path inventory

Every way a journal's files change on disk today. Sync has to account for each one: a change that reaches a file without being recorded is a change another device never hears about.

`engine/persistence.go` is the single mutation authority for the reflections file, the review archive, and their `.bak` siblings. Each mutation is a read-modify-write: read and parse, validate, write the pre-mutation bytes to `<file>.bak`, then replace the file through a temporary file and one rename.

Every mutation runs inside `engine/commit.go` `Journal.Commit`, which holds the journal lock from the read to the replacement. The lock is never held while the author writes in the form or while the review harness runs: both happen between a read and a commit, and the commit re-reads.

## Writes Seneca makes

| Command | Call site | Files changed | Shape of the change | Git commit |
| --- | --- | --- | --- | --- |
| `seneca` (daily form, also `--date`, `--blank`) | `cmd/root.go` `runReflection` → `engine/journal.go` `SaveReflection` → `CommitEntries` | reflections file, its `.bak` | A new day is one entry appended, or inserted in date order for a `--date` backfill. An existing day is re-rendered in place. Every other entry keeps its bytes. | `seneca: reflection DATE` or `seneca: edit reflection DATE` |
| `seneca sort` | `cmd/sort.go` `runSort` → `engine/journal.go` `Sort` → `CommitEntries` | reflections file, its `.bak` | Entries reordered by date. No entry's bytes change. Nothing is written when the file is already what the sort would produce. | `seneca: sort N entries` |
| `seneca delete --date <day>` | `cmd/delete.go` `runDelete` → `engine/reflection_delete.go` `DeleteReflection` → `CommitEntries` | reflections file, its `.bak` | One day's entry removed after it is shown and confirmed (`--yes` skips the question; without a terminal `--yes` is required). Conditional on the entry's bytes as shown: a changed entry is refused as stale, and a day with an open sync conflict is refused. A synced journal records an explicit deletion. Drafts and recordings are untouched. | `seneca: delete reflection <day>` |
| `seneca merge <source>` | `cmd/merge.go` `runMerge` → `engine/journal.go` `Merge` → `CommitEntries` | reflections file, its `.bak` | The source's entries interleaved by date. Refused, with nothing written, when a date appears on both sides. | `seneca: merge N entries` |
| `seneca merge --delete <source>` | `cmd/merge.go` `runMerge` → `os.Remove` | the source file | Removed after the destination is committed. This is the only deletion of a journal-shaped file Seneca performs. The source is kept when the destination's write could not be flushed. | Same commit, with the removal staged |
| `seneca settings init` | `cmd/settings.go` `runSettingsInit` → `engine/journal_settings.go` `InitializeSettings` → `Commit.Metadata` | `<dir>/.seneca/journals/<reflections filename>/settings.json` | The settings document created from the questions and anchor in force. Nothing is written when it exists. No `.bak`; no Markdown and no `config.toml` is read for writing or changed. | `seneca: settings init` |
| `seneca settings set` | `cmd/settings.go` `runSettingsSet` → `engine/journal_settings.go` `UpdateSettings` → `Commit.Metadata` | the same file | The `reflection` unit replaced whole, after it validates whole and only when the document is still at the revision the change was decided on. Nothing is written when it already says what was asked. | `seneca: settings update` |
| `seneca pack apply` | `cmd/pack.go` `runPackApply` → `engine/practice.go` `ApplyPracticePack` → `Commit.Metadata` | the same file | The `reflection` unit replaced by the pack's questions and anchor, and the pack recorded whole in `practice` as in force from today (replacing a pack recorded for the same day), as version 2 of the document; created with a `legacy` unit when it did not exist. Only when the settings are still at the revision the pack was chosen against. Nothing is written when the pack is already in force with its own questions. | `seneca: pack apply <id>` |
| `seneca focus set <text>` | `cmd/focus.go` `setFocus` → `engine/journal.go` `SetFocus` → `AppendRecords` | review archive, its `.bak` | One focus record appended. Creates the archive, with its header, when there is none. | `seneca: focus set DATE` |
| `seneca focus clear` | `cmd/focus.go` `clearFocus` → `engine/journal.go` `ClearFocus` → `AppendRecords` | review archive, its `.bak` | One focus record appended. Nothing is written when no focus is active. | `seneca: focus clear DATE` |
| `seneca review` (on save) | `cmd/review_save.go` `saveReview` → `engine/journal.go` `SaveReview` → `AppendRecords` | review archive, its `.bak` | One review record, plus one focus record when a focus was accepted, appended in a single write. | `seneca: PERIOD review START to END` |
| First append to an older archive | `engine/archive_record.go` `UpgradedHeader` | review archive | The header's `seneca:archive` marker line is restamped to the current schema version. It is the only line of an existing archive Seneca ever rewrites. | Part of the append's commit |

### Side effects of those writes

| Effect | Call site | Notes |
| --- | --- | --- |
| `<file>.bak` | `engine/persistence.go` `writeBackupFile` | The bytes the mutation replaced, written atomically before the primary. Only the latest is kept. No backup is written for a file that was missing or empty. |
| Journal lock | `engine/journal_lock.go` `acquireDirLock`, with `engine/journal_lock_unix.go`, `engine/journal_lock_windows.go`, and `engine/journal_lock_other.go` | `<dir>/.seneca/directory/lock`, held for the length of one commit. It is an advisory lock on an open file, so a process that dies leaves nothing stale. The file is removed on release and the directories made for it are pruned when empty: a journal with nothing else under `.seneca/` has no `.seneca/` between writes. One lock covers every journal in the directory, because they share the archive. A commit that cannot get it within ten seconds fails without writing. |
| Commit record | `engine/commit.go` `applyGroup`, `recoverLocked` | `<dir>/.seneca/directory/commit/`, used only by a commit that changes more than one file. The new contents of every file are staged there, then `record.json` names each file with the revision it replaces and the revision it becomes; that rename is the commit point. The files are then replaced, the record removed, and the directory with it. No command changes more than one file on a journal that is not enrolled in sync: the settings commands change the settings document alone. On an enrolled journal every commit does, because it carries its sync record. |
| Sync history | `engine/sync_state.go` `recordSync`, `record`, `storeObject`; `engine/sync_enroll.go` `EnrollSync`, `JoinSync` | Only for a journal enrolled in sync. Every commit adds one manifest under `.seneca/journals/<reflections filename>/sync/transactions/` and replaces `sync/state.json`, in the commit itself; an edit found in the files is recorded as a manifest of its own first. The contents a manifest names are written to `sync/objects/` ahead of the commit: they are named by their digest and never change, so one left by a commit that failed is harmless. Enrolling and joining also write `.seneca/directory/sync.json`; `seneca sync enroll` does both (`cmd/sync.go` `runSyncEnroll`). |
| Import | `engine/sync_exchange.go` `ImportSync`, `integrate` | Replaces the reflections file, the archive, or the settings document with the changes of each transaction it applies, through the same transactions, backups, and refusals as a local write, together with the manifests it stored and the state, as one commit. Run by `seneca sync once`, by `seneca sync watch`, and by every command in the table above before it prepares its edit (`cmd/sync_cycle.go` `runSyncCycle`). |
| Resolve and recover | `engine/sync_conflict.go` `ResolveSyncConflict`, `ResolveFocusDispute`, `RecoverSyncFile` | Replaces the journal file holding the conflicted artifact with the chosen version, appends one focus record that settles a disputed day, or writes back the artifacts a suspended file lacks, each with the manifest that records it and the state, as one commit through the same transactions, backups, and refusals. Run by `seneca sync resolve` and `seneca sync recover` (`cmd/sync.go`), which commit the files replaced as `seneca: sync resolve ARTIFACT`, `seneca: sync resolve focus DATE`, or `seneca: sync recover FILE`. |
| The exchange | `engine/sync_exchange.go` `PublishSync`, `DirectoryTransport` | A directory outside the journal: `journal.json`, `transactions/`, and `objects/`. Each file is written under a temporary name and renamed into place, and never changed afterwards. A device writes only its own manifests there. Every command that changes the journal publishes on its way out, and returns without waiting for the file service to deliver. |
| Kept drafts | `engine/draft.go` `RetainDraft`, `RetainReviewDraft`, `DiscardDraft` | `<dir>/.seneca/journals/<reflections filename>/drafts/<date>.json` when a daily save fails or is refused, and `<dir>/.seneca/directory/drafts/review-<period>-<start>-to-<end>.md` when a review cannot be archived. A reflection draft is put back into the form by the next run for that day and removed once the day is saved. Drafts are device-local and never part of a commit. |
| Leaving sync | `engine/sync_leave.go` `LeaveSync` | Renames `.seneca/journals/<reflections filename>/sync/` to `sync-left-<UTC time>/` beside it, under the journal lock, and removes `.seneca/directory/sync.json` when it names this journal. No journal file is touched and nothing is deleted: the old history, with every version of any open conflict, stays where it was moved. Run by `seneca sync leave` (`cmd/sync.go`) and the bridge's `sync.leave`. |
| Recovery export | `engine/recovery_export.go` `ExportRecovery` | A new directory the author names, outside the journal: the reflections file and the archive byte for byte, `settings/`, `conflicts/` (every version of every open conflict), `drafts/`, `MANIFEST.json`, and `README.txt`. Written into a hidden `.<name>.partial-<random>` sibling and renamed into place last, so it appears whole or not at all; a failure removes the hidden directory and the next export removes one an interrupted process left. Nothing in the journal changes. Run by `seneca backup` (`cmd/backup.go`) and the bridge's `recovery.export`. |
| `.seneca-*.tmp` | `engine/persistence.go` `AtomicWriteFile` | A temporary file in the destination's own directory, renamed over the destination. Removed on every failure path; a crash between create and rename can leave one behind. |
| Whole-file framing | `engine/reflection_document.go` `RenderReflectionEntries` | Every rewrite of the reflections file emits each entry followed by one `---` line and one blank line. A journal with other spacing around its separators is settled into that form by its first rewrite. Entry bytes are not affected. |
| Directory creation | `cmd/root.go` `ensureDir` | The daily form, `merge`, `focus set`, `settings init`, and a review save create the journal's directory when it is missing, and only after asking at the terminal. |
| Git | `cmd/git.go` `gitCommitPaths` | `git add -A -- <paths>` then `git commit -- <paths>` in the file's directory, naming only the files the command changed. Skipped with a warning outside a repository. A commit failure is a warning, never a rollback: the file is already written. |
| Git, for an import | `cmd/sync_cycle.go` `settleGit` → `cmd/git.go` `commitPaths` | The journal files an import replaced, and only those, committed as `seneca: sync import` with the same path-scoped staging. Whatever else is staged stays staged and uncommitted; nothing under `.seneca/` but the settings document is ever named. Nothing is imported or committed while `cmd/git.go` `gitBusy` finds a merge, rebase, cherry-pick, revert, or bisect under way, or a journal file unmerged. |
| Git retry note | `cmd/sync_cycle.go` `noteGitPending`, `settleGit`, `clearGitPending` | `<dir>/.seneca/journals/<reflections filename>/desktop/git-pending.json`: the files an import replaced that Git does not have yet, with the last failure. Written before the commit is attempted and removed when it succeeds, so a commit that failed is retried by the next exchange without importing anything again. Device-local and never committed. |
| Usage ledger | `cmd/review_usage.go` `appendUsageRecord`, through `engine/persistence.go` `AtomicWriteFile` | `<dir>/.seneca/journals/<reflections filename>/desktop/usage.jsonl`: one content-free line appended for every `seneca review` attempt that reached its harness, whatever its outcome, written after the outcome is known. Created by the first such write, never by a read; `seneca usage` and `seneca doctor` only read it. A failure to write it is a warning and never fails the review. Its read and replacement run under the journal lock (`engine.WithDirectoryLock`), so reviews finishing at the same instant each keep their line; a lock still busy after the wait is a warning like any other ledger failure. Device-local and never committed or exchanged. |
| Receipt | `engine/sync_receipt.go` `PublishSyncReceipt` | `<exchange>/receipts/<device>/<sha-256>.json`: how far this device has applied each device's transactions, read from its own sync state. Written by `cmd/sync_cycle.go` `runSyncCycle` and `syncAfter` after publishing, and only while nothing imported still waits for its Git commit; on the phone by the bridge's `sync.export`. Immutable, written only when what was applied grew, and never read back into the journal. |
| iCloud download requests | `cmd/sync_cloud.go` `(*cloudExchange).request` | Changes nothing in the journal or the exchange: for each file of the exchange that iCloud Drive lists on this Mac and has not downloaded (a `.<name>.icloud` placeholder, or a dataless file), runs `brctl download <path>` (`SENECA_BRCTL` names the program) so a later exchange finds it. Run only by an exchange, never by `seneca sync status`. Such a file is never read while it is away; the engine is told it has not arrived. |
| Background service | `cmd/sync_service.go` `runSyncServiceInstall`, `runSyncServiceRemove` | `~/Library/LaunchAgents/io.sglavoie.seneca.sync.plist`, written and handed to `launchctl` only by `seneca sync service install`, and removed by `seneca sync service remove`. It runs `seneca sync watch` (`cmd/sync_watch.go`) and logs to `~/Library/Logs/seneca-sync.log`. Neither command touches the journal. |
| The iPhone app | `mobile/senecabridge` → the `engine.Journal` operations above | Every write the phone makes to a journal is one of the engine calls in this inventory, made through the [bridge](bridge.md): there is no bridge-only write path, and the phone runs no Git. The bridge itself writes one file, the request ledger `requests.json`, in the app's own state directory outside the journal: the answers it gave to the mutations it carried out, so that a repeated request is answered instead of repeated. Device-local and never exchanged. | Review scratch files | `cmd/review_harness.go` `runReviewHarness` | A schema file and, for one harness, an output file in the system temporary directory, removed when the harness returns. Never in the journal's directory. |

## Writes Seneca does not make

These reach the same files without passing through the persistence layer.

| Source | How | What Seneca does about it |
| --- | --- | --- |
| A text editor | The author edits the reflections file or the archive by hand. `seneca open` launches the configured editor (`cmd/open.go`), but any editor will do. | Nothing is watched unless `seneca sync watch` is running; it notices the change and records it, and changes nothing else about what follows. The next command reads whatever is there, and each mutation re-reads the file immediately before writing. An editor does not take the journal lock; a hand edit to the very day an open form is editing is caught by the form's base revision like any other writer's. A hand edit that leaves the file ambiguous (a repeated date, an undatable entry, an archive record whose ID no longer matches its content) makes every write refuse until it is fixed; `seneca doctor` names the problem. |
| Git | `git pull`, `checkout`, `restore`, `stash`, a merge, or a rebase replaces file contents wholesale. | The same as a hand edit. A Git conflict marker inside a file is just malformed content. |
| An AI harness | `seneca review` runs an external program that the author configured. | Seneca passes it a prompt and reads its answer. It is given no path to write to, but nothing stops it from writing. |
| Another Seneca process | Two commands at once, or a command and the background watcher, on one machine. | Each commit takes the journal lock and re-reads under it, so the second writer builds on what the first wrote. A daily save carries the revision of the entry the form was opened on: when that day was written, changed, or removed meanwhile, the save is refused with nothing written and the author's writing is kept as a draft. Days other than the draft's own, and archive records, are append-only from a writer's point of view and simply both land. |
| A file-syncing service | iCloud Drive, or anything else that replaces files behind a running program. | The same as a hand edit. It does not take the lock, so a replacement that lands between a commit's read and its rename is still lost; the lock is advisory and is not relied on across machines. |

## What this means for sync

- The seven command rows are the complete set of local commits. Each one is the point at which a transaction is recorded: on an enrolled journal the sync record joins the same `Journal.Commit`, which makes the pair one recoverable unit.
- External changes cannot be prevented, so they are detected: an artifact whose bytes differ from the last recorded state, with no transaction to explain the difference, is an external change, and is recorded as one before anything arriving is applied.
- The format, and the rules for applying what arrives, are on the [sync format](sync-format.md) page.
- Concurrent Seneca writers are serialized by the journal lock, which covers the reflections file, the archive, and everything under `.seneca/` alike.
- An interrupted grouped commit is completed, or discarded, by the next operation on the journal — read or write — before it does anything else. A record whose files something else changed in the meantime is not completed: the journal refuses writes and names the directory holding what was being written.
- `.bak`, `.seneca-*.tmp`, the lock, the commit record, kept drafts, `sync/state.json`, the Git retry note, and the usage ledger are local. They are never exchanged between devices.
